class="available-content"><div class="body markup" dir="auto"><p>This practitioner paper treats agent memory as harness engineering: mechanisms that decide what stays in a language model’s prompt window, what moves out, and what returns. Those mechanisms often fail in ways that look like forgetting, because no error is raised at the point of failure.</p><div><hr/></div><h2 class="header-anchor-post"><strong>Abstract</strong><div class="pencraft pc-display-flex pc-alignItems-center pc-position-absolute pc-reset header-anchor-parent"><div class="pencraft pc-display-contents pc-reset pubTheme-yiXxQA"><div class="pencraft pc-reset header-anchor offset-top" id="§abstract"></div><button class="pencraft pc-reset pencraft iconButton-mq_Et5 iconButtonBase-dJGHgN buttonBase-GK1x3M buttonStyle-r7yGCK size_sm-G3LciD priority_secondary-S63h9o" tabindex="0" type="button" data-href="https://rickhigh.substack.com/i/215895006/abstract"><svg xmlns="http://www.w3.org/2000/svg" width="18" height="18" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-link"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></button></div></div></h2><p>This paper treats agent memory as harness engineering: mechanisms that decide what stays in a language model’s prompt window, what moves out, and what returns. It documents retention and eviction policies in LangGraph checkpointing and store persistence, MemGPT and Letta paging and compaction, Mem0 extraction and expiration handling, recency, importance, and decay-based retrieval scoring, Zep bi-temporal supersession, reciprocal rank fusion, a seven-point retrieval-failure taxonomy tied to chunking, and two defects that corrupt benchmark scoring independent of harness quality.</p><p>Figure 1 shows the production loop a memory item travels. Figure 2 shows the paging boundary a reload must cross. Figure 3 contrasts saliency scoring with recency weighting on the retain-versus-evict decision. Figure 4 traces rank-only fusion to a wrong-but-ranked result that reaches context undetected. Figure 5 contrasts thread-scoped checkpoints against a cross-thread store. Figure 6 adds the restore hazard: replay from a checkpoint can duplicate an external side effect.</p><p>Each finding traces to a published design, vendor documentation, or a small cluster describing one system, uncorroborated by cross-architecture production measurement. The contribution is a mechanism-level account of how retention, eviction, and reload fail without raising an error, alongside a limitations section stating where each claim’s support stops short of settled fact, and a labeled recall probe an implementer can run against a production index.</p><div><hr/></div><h2 class="header-anchor-post"><strong>Introduction</strong><div class="pencraft pc-display-flex pc-alignItems-center pc-position-absolute pc-reset header-anchor-parent"><div class="pencraft pc-display-contents pc-reset pubTheme-yiXxQA"><div class="pencraft pc-reset header-anchor offset-top" id="§introduction"></div><button class="pencraft pc-reset pencraft iconButton-mq_Et5 iconButtonBase-dJGHgN buttonBase-GK1x3M buttonStyle-r7yGCK size_sm-G3LciD priority_secondary-S63h9o" tabindex="0" type="button" data-href="https://rickhigh.substack.com/i/215895006/introduction"><svg xmlns="http://www.w3.org/2000/svg" width="18" height="18" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-link"><path d="M10 13a5 5 0 0 0 7.54.54l3-3a5 5 0 0 0-7.07-7.07l-1.72 1.71"></path><path d="M14 11a5 5 0 0 0-7.54-.54l-3 3a5 5 0 0 0 7.07 7.07l1.71-1.71"></path></svg></button></div></div></h2><p>Main context is the portion of an agent’s state held directly in the language model’s prompt window, available to condition generation. External context is state held outside that window, with no effect on the model’s output until an explicit operation moves it back in. On a source describing one architecture, MemGPT treats main context as an analog of RAM and external context as an analog of disk, a paging model in which nothing in external context can influence a generation step until it is paged in [1]. Read this as one system’s memory-management model rather than a property every agent harness shares.</p><p>The alternative to paging is holding the full history directly in the prompt window at all times. That alternative removes the need for any eviction or reload logic, but it caps how long a task’s history can grow before the window fills, and it lets stale content compete with what the current step actually needs. The cost of choosing paging instead is the eviction and reload machinery itself, which can misfire silently: a page-out decision that discards a fact still needed later, or a page-in decision that never fires, both leave the agent behaving as though it forgot something, with no error raised at the point of failure.</p><p>The remainder of this paper takes up that silent-failure property as it appears in four distinct mechanisms, rather than treating “the agent forgot” as one undifferentiated event.</p><ol><li><p>An address-space boundary that is crossed only by explicit action.</p></li><li><p>A scoring function whose components fail independently.</p></li><li><p>A persistence layer split by scope: thread-local snapshots versus cross-thread memory.</p></li><li><p>A retrieval pipeline whose failures do not share one diagnosis.</p></li></ol><p>Published taxonomies disagree about where those failures belong. One interaction-centric scheme assigns 36 of 41 role-specific failure modes to the model [21]. Other schemes treat system design, context brittleness, memory, and tool-calling as first-class non-model classes [21]. The attribution boundary remains unsettled, and the two answers carry different remediation budgets. Attributing a failure to the model implies retraining or swapping the model. Attributing it to the harness implies changing retention, eviction, and reload policy. This paper organizes agent memory as three explicit harness decisions rather than one retrieval add-on. Retain fixes what a run writes to durable memory and on what trigger. Evict fixes what leaves the working context and what becomes unrecoverable once it does. Reload fixes what is read back and whether a partial read is detected or simply ranked and returned.</p><div><hr/></div><p>If you are a paid subscriber, thank you.
